純粋コアの検査

14 個の登録定理

逐次・単一資源の数量予約モデルを、Lean 4.19.0で検査済み。

開発版のGitバンドルには、同じ14定理をLean 4.36.0の6カーネルで検査した記録も収録しています。

ソースに含まれるもの

仕様を資産にする

成功・拒否の条件、前提、具体例を、実装から独立した契約として残します。

変更を検証する

新しい実装を同じ契約に照らします。証明を通すために要求を緩めない設計です。

証拠を持ち運ぶ

仕様、証明、対象バージョン、検査記録を一緒に保ち、手元で確認できます。

このデモで、確かめたこと。

正しく成功する

許される数量の予約・解放は、定義された正確な増減を行います。

拒否で状態を変えない

条件を満たさない操作は拒否し、元の状態を返します。

数量を保存する

モデル内の任意の有限操作列で、容量の不変条件が維持されます。

この証明は単一資源を逐次操作する純粋コアが対象です。個別予約の所有権、認証、データベースの並行更新、再送、障害復旧、コンパイラやOSの正しさは対象外です。

Check changes to reservation logic

A reservation for every remaining unit should succeed. A request for one extra unit should leave the inventory untouched. Lean Regen supplies a fixed contract, 14 checked theorems and three intentionally broken implementations that the checks reject.

Download the source ZIP, extract it and run the quickstart commands from the directory containing README.md. Use Python 3.11 or later and the official Lean/Lake 4.19.0 toolchain. You can compare the file hashes, rebuild the source archive and rerun the checks offline once the tools are installed.

What the evidence covers

The proofs cover sequential reserve and release operations on one resource. Database concurrency, per-user authorization, crash recovery and deployed application behavior need their own checks. The offline development bundle includes a separate six-kernel run on the same 14 obligations under Lean 4.36.0.

Free local use requires no account. Hosted checking, enrollment and payments are offline. The project is released under Apache-2.0.
