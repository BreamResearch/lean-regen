差し替えの手順

振る舞いを決める

入力、状態、必ず受理する場合、拒否する場合、操作後に観測できる結果を定めます。

候補を実装する

合意した仕様を固定し、新しい実装とその証明を用意します。通常の更新でも仕様・許容公理・検査条件を維持します。

同じ条件で検査する

候補の証明を固定した条件で検査します。データベースへの書き込みなど、モデルの外にある動作は別に照合します。

別の業務にもこの手順を使えます。たとえばデータ形式の変換器なら、受け付ける入力、エラー条件、出力形式を先に決め、その契約と証明を用意してから変換処理を差し替えます。

同じ契約で3つの実装を検査する

参照設計のZIPを展開し、Python 3.11以上と公式Lean/Lake 4.19.0を用意します。手元にあるツールのbinディレクトリと、新しい出力先を指定してください。Apple SiliconのmacOS 27では、先に同梱READMEの手順でXcodeのリンカーを選択します。

リリースと配布ファイル

cd lean-regen-reference
python3 compare.py \
  --tool-bin /absolute/path/to/lean-4.19.0/bin \
  --out ../comparison

期待される結果は、元の実装と動作の等しい書き換えが各14項目を通過し、残り全数の予約を拒否する実装が検査で止まることです。

残り8枠を、すべて予約できるか。

空き8・予約済み2の状態で8枠を予約すると、契約は受理し、空き0・予約済み10を返します。空きより多い要求と数量0の要求は拒否し、残高を維持します。

SQLiteの比較用実装で「空き以下」を「空き未満」に変えると、合計10枠は保たれたまま、正当な予約を拒否しました。記録上、最初の不一致は4件目です。

Write down the behavior your software promises in Lean. When you rewrite the implementation, check it against the same conditions. Lean Regen shows how to organize the specification, implementation and proofs.

How to replace an implementation

Specify the behavior

Define inputs, state, when the system must accept or reject a request, and what a caller can observe afterwards.

Build a candidate

Freeze the agreed specification. Supply a new implementation and its proof. Routine changes keep the same specification, permitted axioms and acceptance checks.

Check the candidate

Check its proof against the original conditions. Test effects outside the model, such as database writes, against what the application actually records.

For a different domain, a data-format converter could preserve its accepted inputs, error conditions and output format across a rewrite. Applying this design there requires a contract and proofs specific to the converter.

Check three implementations against one contract

Extract the reference design ZIP. Use Python 3.11+ and the official Lean/Lake 4.19.0 toolchain. Supply the path to its bin directory and choose a fresh output directory. On Apple Silicon with macOS 27, first follow the ZIP’s README to select the Xcode linker.

Worked example · Reservations for one resource

Can you reserve all eight remaining units?

Start with eight available and two reserved. A request for eight must succeed and leave zero available and ten reserved. A request for more than eight or for zero must be rejected without changing either balance.

Changing an inclusive comparison to a strict one in the sample SQLite implementation rejected a valid reservation. Both balances still added up to ten. The first divergence was transaction four.

What the Lean proofs cover

The model handles sequential operations on one resource. Its 14 checked obligations include exact updates on acceptance, unchanged state on rejection and conservation across any finite sequence. Per-user ownership, concurrent updates and crash recovery require their own checks.

How to supply a journal and interpret a result

Export the initial balances for one resource, then each reserve or release decision and its committed balances in commit order as JSONL. Remove transport retries and finish with the transaction count.

python3 lean-regen-check.pyz my-trace.jsonl

The 1,153 bundled reference inputs cover every valid state at capacities 0–10 with quantities from zero through capacity plus one, and nine selected cases at the signed 64-bit limit. Other inputs are reported as outside coverage. A native mode supports additional inputs with Python 3.11+ and the official Lean/Lake 4.19.0 toolchain. A match applies to the supplied initial state and recorded transactions.
