業務の約束を引き継ぐ

AIや新しいライブラリでコードを書き換えたとき、前と同じ業務ルールを守っているか。Lean Regenでは、人が決めたルールをLeanの仕様にし、次の実装がそれを満たす証明を検査します。仕様に表した性質は、新旧のコードを一行ずつ比較しなくても確かめられます。

人が決めること、更新のたびに検査できること

意図を具体例で決める

「残り8枠をすべて予約してよいか」は業務上の判断です。担当者が受理と決めたら、成功後の残高と、拒否したときに変えてはいけない状態まで仕様に書きます。

実装と証明を組にする

担当者やAIが別の実装を書き、その版に対応する証明を用意します。元の条件を満たす証明が通れば、その性質を確認するためのコードレビューを毎回繰り返さずに済みます。

判断と根拠を引き継ぐ

後任は、ルールの意味や過去の反例、どの版で何を検査したかをたどれます。業務の方針を変えるときは仕様を改め、DBへの書き込みや並行処理はそれぞれの前提に沿って検査します。

在庫はこの方法を試せる一例です。たとえばデータ形式の変換器でも、受け付ける入力、エラー条件、出力を定めれば、その仕様に対して別の変換処理を検査できます。

応用例 Knot で、複数案件の配分を確かめる

同じ振替元に2件の依頼が重なったとき、1件ずつなら足りるのに、合算すると確約済みの枠を侵します。案を修正して確定し、会計期間・案件の依存・仕訳への影響をブラウザーで確認できます。Odoo Community への書き込み中に台帳を切り替えて復帰した実測結果も、登録不要で確認できます。

残り8枠を、すべて予約できるか。

空き8・予約済み2の状態で8枠を予約すると、契約は受理し、空き0・予約済み10を返します。空きより多い要求と数量0の要求は拒否し、残高を維持します。

Keep the business rules when the code is rewritten

When AI rewrites a function or a library is replaced, how do you know the business rules still hold? Lean Regen records the rules people agree on in a Lean specification. Each replacement comes with a proof against those rules. For a property covered by the proof, you can check it again without rereading the entire diff.

What people decide and what a proof can check

Agree on a concrete case

Can a customer reserve all eight remaining units? People who know the business decide. If the answer is yes, write down the resulting balances and what must stay unchanged when a request is rejected.

Pair the code with a proof

A developer or an AI can write a new implementation and supply its proof. For a property in the fixed specification, checking that proof can replace a fresh line-by-line review of the change.

Keep the reasoning available

The next maintainer can recover the meaning of the rule, earlier counterexamples and the results for each version. A change in business policy calls for a new decision. Database writes and concurrency have separate assumptions to check.

Inventory is one worked example. For a data-format converter, define its accepted inputs, errors and expected outputs. Those become the specification against which to check a replacement converter.

Worked example · Reservations for one resource

Can you reserve all eight remaining units?

Start with eight available and two reserved. A request for eight must succeed and leave zero available and ten reserved. A request for more than eight or for zero must be rejected without changing either balance.

Changing an inclusive comparison to a strict one in the sample SQLite implementation rejected a valid reservation. Both balances still added up to ten. The first divergence was transaction four.

What the Lean proofs cover

All three implementations are checked against the same specification, theorem statements and permitted axioms. The model handles sequential operations on one resource. Its 14 checked obligations include exact updates on acceptance, unchanged state on rejection and conservation across any finite sequence. Per-user ownership, concurrent updates and crash recovery require their own checks.

How to supply a journal and interpret a result

Export the initial balances for one resource, then each reserve or release decision and its committed balances in commit order as JSONL. Remove transport retries and finish with the transaction count.

python3 lean-regen-check.pyz my-trace.jsonl

The 1,153 bundled reference inputs cover every valid state at capacities 0–10 with quantities from zero through capacity plus one, and nine selected cases at the signed 64-bit limit. Other inputs are reported as outside coverage. A native mode supports additional inputs with Python 3.11+ and the official Lean/Lake 4.19.0 toolchain. A match applies to the supplied initial state and recorded transactions.
